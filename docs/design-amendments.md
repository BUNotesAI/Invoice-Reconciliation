# 冻结设计勘误

`docs/design.md`（v1.0）冻结不改；经外环裁定的勘误记在这里，按编号引用。

## A1 · 日限额执行与示例政策额度（2026-09-27，外环裁定，出自 P1 review）

**问题**：示例政策的餐饮日限（150 元）与市内打车日限（50 元）和 §10.1 期望冲突：F05（52.00，单日打车）标「自动」，F09（386.00，单日餐饮）只标「核对视觉读数」。

**裁定**：

1. 日限额照政策执行，从 P2 起：按申请人、服务日期、类别合计后与限额比较；超标项进入待判断，由申请人说明、财务审核。住宿仍按「晚数 × 每晚标准」比较。
2. 示例政策 `local_taxi_per_day_cents` 改为 10000（100 元/天），`meal_per_day_cents` 保持 15000。F05 不再超标。F09 超餐饮日限，但它本来就因视觉读数待判断，只多一条理由：报告计数仍是 6/4/2，入账 10 张、合计 4,901.40 不变。
3. 边界集增加「同一天两笔打车合计超过 100 元 → 待判断」（`fixtures/edge/link/` 的 R07、R08：60 + 55 = 115 元）。
4. `fixtures/expected/link.json` 相应记录 F09 的超标理由。

**实现口径**（P2）：日限额按发票事实所示类别（餐饮、市内客运）与服务日期合计，不按类别标签；只对可信事实计算。F09 在第一遍仍是视觉 candidate，不参与日限合计，理由只有 `FACT_UNCONFIRMED`；用户确认票面后重新关联，才出现 `OVER_LIMIT`，申请人补充说明后记为 `OVER_LIMIT_EXPLAINED`，交财务审核。

## A2 · 终审由六项变为七组（2026-09-27，外环裁定，出自 P1 对抗审查）

**问题**：P1 对抗审查（A3、A4）指出终审只复算了「表 ↔ 快照」，没有复算「快照 ↔ 原件」和「显示 ↔ 值」。

**裁定**：

1. 终审在 §5.6 的六项之外增加第七组 `source_facts`：文字层原件用终审自己的解析重读票号、小写金额、购买方、入住离店；图片票复核确认绑定；按政策复核抬头、类别与发票事实、住宿超标、重开票约束。另外按快照独立重建期望工作簿，与磁盘文件逐字节比对。
2. 设计 DoD 与剧本中的「六项终审 6/6」一律读作「全部检查组全绿」。
3. 面向用户的回帖文案写「终审全部通过（7/7）」。
4. 政策类别新增必填字段 `kind`（lodging / meal / local_taxi / air / other），规则按发票事实触发，类别须与事实一致。
